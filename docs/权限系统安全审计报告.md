## 一、审计概述

本次审计对 CompostLab v2 项目的权限系统进行了全面检查，涵盖：
- 后端认证和授权机制
- 前端路由守卫和 UI 层权限控制
- 角色权限隔离和访问控制
- 敏感信息保护
- 输入验证和注入防护

### 权限系统架构
```
认证层: JWT Token + Basic Auth (向后兼容)
  ↓
授权层: 基于角色的访问控制 (RBAC)
  - readonly (只读用户)
  - operator (操作员)
  - admin (管理员)
  - superuser (超级管理员)
  ↓
审计层: 完整的操作日志记录
```

#### 问题 1.1: 设备注册接口缺乏身份验证 ✅ 已修复
**严重程度**: 🔴 高危  
**文件**: `apps/devices/api.py:1270-1353`  
**类型**: 安全漏洞 - 身份验证绕过

**问题描述**:
`DeviceRegisterView` 虽然使用了 `BasicAuthMixin` 和 `JsonBodyMixin`，但这只意味着它支持认证，并非强制要求。如果设备通过 MQTT 调用此接口，可能绕过认证直接注册设备。

```python
@method_decorator(csrf_exempt, name="dispatch")
class DeviceRegisterView(BasicAuthMixin, JsonBodyMixin, View):
    def post(self, request):
        body = self.json_body(request)
        # ... 设备注册逻辑
```

**影响**:
- 恶意设备可以伪造注册
- 攻击者可以创建未授权的设备条目
- 可能导致数据污染和系统混乱

**修复方案**: ✅ 已实施
采用 **方案 2: 使用 JWT with device claims**

1. 创建了 `DeviceJWTAuthMixin` 专用认证 mixin (`apps/api/mixins.py`)
   - 支持设备自注册 JWT Token（包含 `device_code` claim）
   - 支持管理员注册 JWT Token（需要 `is_staff` 或 `role='admin'`）
   - 严格的 token 验证逻辑

2. 修改 `DeviceRegisterView` 使用新的认证 mixin
   - 替换 `BasicAuthMixin` 为 `DeviceJWTAuthMixin`
   - 添加 device_code 一致性验证（设备自注册时）
   - 区分注册类型（`self` 设备自注册 / `admin` 管理员注册）

**修复后的代码**:
```python
# apps/api/mixins.py 新增

    """
    
    def dispatch(self, request, *args, **kwargs):
        # ... 验证逻辑
```

```python
# apps/devices/api.py 修改

    def post(self, request):
        # 提取 device_code 优先级：JWT token > MQTT topic > request body
        # 对于设备自注册，验证 token 中的 device_code 与请求中的 device_code 是否一致
```

**安全性改进**:
- ✅ 设备注册现在必须通过 JWT 认证

#### 问题 1.3: 用户权限检查存在逻辑错误
**严重程度**: 🔴 高危  
**文件**: `apps/accounts/utils.py:117-153`  
**类型**: 逻辑错误 - 权限提升

**问题描述**:
`has_permission` 函数在检查 `is_staff` 用户时，允许其访问所有角色（readonly/operator/admin），这可能不是预期的行为。通常 `is_staff` 用户应该只能访问 admin 级别的权限。

```python
# 管理员（Django staff）也算 admin 角色
if user.is_staff and required_role in ["readonly", "operator", "admin"]:
    return True
```

**影响**:
- Django staff 用户可能获得超出预期的权限
- 权限边界模糊，难以审计
- 可能违反最小权限原则

**修复方案**:
```python
def has_permission(user, required_role):
    """
    检查用户是否有足够权限
    
    Args:
        user: User 对象
        required_role: 需要的最低角色（readonly/operator/admin）
    
    Returns:
        bool: 是否有权限
    """
    if not user or not user.is_authenticated:
        return False
    
    # 超级用户总是有权限
    if user.is_superuser:
        return True
    
    # Django staff 用户需要有对应的 profile role
    # 不再自动赋予 admin 权限
    if user.is_staff:
        try:
            profile = user.profile
            # staff 用户必须有 admin 角色
            return profile.role == "admin"
        except UserProfile.DoesNotExist:
            return False
    
    try:
        profile = user.profile
    except UserProfile.DoesNotExist:
        # 没有 profile 的用户没有权限（除非是只读请求）
        return False
    
    if not profile.is_active:
        return False
    
    # 角色等级：readonly < operator < admin
    role_levels = {"readonly": 1, "operator": 2, "admin": 3}
    user_level = role_levels.get(profile.role, 0)
    required_level = role_levels.get(required_role, 999)
    
    return user_level >= required_level
```

#### 问题 1.4: JWT Token 黑名单缺失
**严重程度**: 🔴 高危  
**文件**: `apps/accounts/api.py:142-156`  
**类型**: 安全漏洞 - Token 无法撤销

**问题描述**:
`LogoutView` 只是记录日志，但无法使 JWT Token 失效。JWT 是无状态的，签发后无法在服务器端撤销，直到过期。这意味着：

1. 用户登出后，token 在有效期内仍然可以使用
2. 管理员无法强制用户下线
3. 密码修改后，旧的 token 仍然有效

```python
@method_decorator(csrf_exempt, name='dispatch')
class LogoutView(JWTAuthMixin, View):
    def post(self, request):
        log_audit(
            request.user,
            AuditLog.Action.LOGOUT,
            description=f"用户登出：{request.user.username}",
            request=request,
        )
        return JsonResponse({"detail": "Logged out successfully."}, status=200)
```

**影响**:
- Token 泄露后无法及时撤销
- 安全事件响应延迟
- 无法实现强制登出功能

**修复方案**:
```python
# 方案 1: 使用 Redis Token 黑名单
import redis
from rest_framework_simplejwt.tokens import RefreshToken

# settings.py
REDIS_CLIENT = redis.Redis(host='localhost', port=6379, db=0)

# utils.py
def revoke_token(jti: str, exp: int):
    """将 token 加入黑名单"""
    ttl = exp - int(time.time())
    if ttl > 0:
        REDIS_CLIENT.setex(f"blacklist:{jti}", ttl, "1")

def is_token_blacklisted(jti: str) -> bool:
    """检查 token 是否在黑名单中"""
    return REDIS_CLIENT.exists(f"blacklist:{jti}")

# api.py
class LogoutView(JWTAuthMixin, View):
    def post(self, request):
        auth_header = request.META.get("HTTP_AUTHORIZATION", "")
        if auth_header.startswith("Bearer "):
            try:
                token = RefreshToken(auth_header.split(" ")[1])
                # 将 refresh token 加入黑名单
                revoke_token(token['jti'], token['exp'])
                # 同时将 access token 加入黑名单
                access_token = token.access_token
                revoke_token(access_token['jti'], access_token['exp'])
            except Exception:
                pass
        
        log_audit(
            request.user,
            AuditLog.Action.LOGOUT,
            description=f"用户登出：{request.user.username}",
            request=request,
        )
        return JsonResponse({"detail": "Logged out successfully."}, status=200)

# JWTAuthMixin 需要检查黑名单
class JWTAuthMixin:
    def dispatch(self, request, *args, **kwargs):
        auth_header = request.META.get("HTTP_AUTHORIZATION", "")
        
        if auth_header.startswith("Bearer "):
            jwt_auth = JWTAuthentication()
            try:
                validated_token = jwt_auth.get_validated_token(auth_header.split(" ")[1])
                # 检查 token 黑名单
                if is_token_blacklisted(validated_token['jti']):
                    return JsonResponse(
                        {"detail": "Token has been revoked"},
                        status=401,
                    )
                user = jwt_auth.get_user(validated_token)
                request.user = user
                return super().dispatch(request, *args, **kwargs)
            except (InvalidToken, TokenError) as e:
                return JsonResponse(
                    {"detail": f"Invalid token: {str(e)}"},
                    status=401,
                )
        # ...
```

#### 问题 1.5: 前端用户信息存储在 localStorage 存在 XSS 风险
**严重程度**: 🔴 高危  
**文件**: `frontend/src/lib/auth.ts:29-44`  
**类型**: 安全漏洞 - XSS 攻击

**问题描述**:
前端将用户信息（包括敏感字段如 role）存储在 `localStorage` 中，如果应用存在 XSS 漏洞，攻击者可以窃取这些信息。

```typescript
export function setUser(user: any) {
    localStorage.setItem("user", JSON.stringify(user));
}

export function getUser(): any | null {
    const str = localStorage.getItem("user");
    return str ? JSON.parse(str) : null;
}
```

**影响**:
- XSS 攻击可以窃取用户身份信息
- 攻击者可以模拟用户操作
- 可能导致会话劫持

**修复方案**:
```typescript
// 方案 1: 使用 HttpOnly Cookie 存储敏感信息（需后端配合）
// 前端只从 API 获取用户信息，不存储敏感字段

// 方案 2: 使用 sessionStorage (关闭页面即失效)
export function setUser(user: any) {
    // 只存储非敏感信息
    const safeUser = {
        id: user.id,
        username: user.username,
        role_display: user.role_display,
        // 不存储 role、is_staff、is_superuser 等敏感字段
    };
    sessionStorage.setItem("user", JSON.stringify(safeUser));
}

// 方案 3: 加密存储
import CryptoJS from 'crypto-js';

const SECRET_KEY = process.env.NEXT_PUBLIC_ENCRYPTION_KEY || 'default-secret';

function encrypt(data: string): string {
    return CryptoJS.AES.encrypt(data, SECRET_KEY).toString();
}

function decrypt(ciphertext: string): string {
    const bytes = CryptoJS.AES.decrypt(ciphertext, SECRET_KEY);
    return bytes.toString(CryptoJS.enc.Utf8);
}

export function setUser(user: any) {
    localStorage.setItem("user", encrypt(JSON.stringify(user)));
}

export function getUser(): any | null {
    const encrypted = localStorage.getItem("user");
    if (!encrypted) return null;
    try {
        return JSON.parse(decrypt(encrypted));
    } catch {
        return null;
    }
}
```

#### 问题 2.1: 缺少请求速率限制
**严重程度**: 🟡 中危  
**文件**: 所有 API 视图  
**类型**: 安全漏洞 - DoS 攻击

**问题描述**:
所有 API 接口都没有实施请求速率限制，攻击者可以通过高频请求导致：

1. 资源耗尽（CPU/内存/数据库连接）
2. 暴力破解密码
3. 枚举用户信息

**修复方案**:
```python
# 安装 django-ratelimit
# pip install django-ratelimit

# settings.py
INSTALLED_APPS = [
    # ...
    'ratelimit',
]

# utils.py
from ratelimit.decorators import ratelimit
from django.core.cache import cache

class RateLimitedMixin:
    """请求速率限制 Mixin"""
    
    def dispatch(self, request, *args, **kwargs):
        # 生成限流 key
        user_id = getattr(request.user, 'id', 'anonymous')
        ip = get_client_ip(request)
        key = f"ratelimit:{self.__class__.__name__}:{user_id}:{ip}"
        
        # 检查速率
        count = cache.get(key, 0)
        if count >= self.rate_limit:
            return JsonResponse({
                "detail": "Too many requests. Please try again later."
            }, status=429)
        
        # 增加计数
        cache.set(key, count + 1, self.rate_period)
        
        return super().dispatch(request, *args, **kwargs)

class LoginRateLimitedView(RateLimitedMixin):
    rate_limit = 5  # 5 次
    rate_period = 300  # 5 分钟

# 使用示例
class LoginView(LoginRateLimitedView, JWTAuthMixin, View):
    def post(self, request):
        # ...
```

```typescript
// 创建权限检查工具
export function hasRequiredRole(userRole: string, requiredRole: string): boolean {
  const roleLevels: Record<string, number> = {
    readonly: 1,
    operator: 2,
    admin: 3,
  };
  return (roleLevels[userRole] || 0) >= (roleLevels[requiredRole] || 999);
}

// 创建角色守卫组件
export function RoleGuard({ 
  children, 
  requiredRole = "readonly" 
}: { 
  children: React.ReactNode;
  requiredRole?: string;
}) {
  const currentUser = getUser();
  const userRole = currentUser?.role || "readonly";
  
  if (!hasRequiredRole(userRole, requiredRole)) {
    return (
      <div style={{ padding: 48, textAlign: "center" }}>
        <Result
          status="403"
          title="权限不足"
          subTitle="您没有权限访问此页面"
          extra={
            <Button type="primary" onClick={() => router.push("/")}>
              返回首页
            </Button>
          }
        />
      </div>
    );
  }
  
  return <>{children}</>;
}

// 在布局中使用
export default function MainLayout({ children }: { children: React.ReactNode }) {

  // 定义页面所需权限

    if (path.startsWith("/scripts")) return "operator";
    return "readonly";
  };
  
  const requiredRole = getPageRequiredRole(pathname);
  
  return (
    <Layout>
      <Sider>...</Sider>
      <Layout>
        <Content>
          <RoleGuard requiredRole={requiredRole}>
            {children}
          </RoleGuard>
        </Content>
      </Layout>
    </Layout>
  );
}
```

#### 问题 2.3: 审计日志可能记录敏感信息
**严重程度**: 🟡 中危  
**文件**: `apps/accounts/utils.py:63-108`  
**类型**: 安全漏洞 - 信息泄露

**问题描述**:
`log_audit` 函数的 `changes` 参数记录完整的变更内容，可能包含敏感信息（如密码、密钥等）。

```python
AuditLog.objects.create(
    user=user,
    username=username,
    action=action,
    resource_type=resource_type,
    resource_id=str(resource_id) if resource_id else "",
    description=description,
    changes=changes,  # 可能包含敏感信息
    ip_address=ip_address,
    user_agent=user_agent,
    success=success,
    error_message=error_message,
)
```

**修复方案**:
```python
def sanitize_changes(changes: dict) -> dict:
    """清理变更内容中的敏感字段"""
    if not isinstance(changes, dict):
        return changes
    
    sensitive_keys = {
        'password', 'token', 'secret', 'key', 'api_key',
        'access_token', 'refresh_token', 'private_key'
    }
    
    sanitized = {}
    for k, v in changes.items():
        if any(sensitive in k.lower() for sensitive in sensitive_keys):
            sanitized[k] = "***REDACTED***"
        elif isinstance(v, dict):
            sanitized[k] = sanitize_changes(v)
        else:
            sanitized[k] = v
    
    return sanitized

def log_audit(
    user,
    action,
    resource_type="",
    resource_id="",
    description="",
    changes=None,
    success=True,
    error_message="",
    request=None,
):
    username = user.username if user else "anonymous"
    ip_address = None
    user_agent = ""
    
    if request:
        ip_address = get_client_ip(request)
        user_agent = request.META.get("HTTP_USER_AGENT", "")[:500]
    
    # 清理敏感信息
    sanitized_changes = sanitize_changes(changes)
    
    AuditLog.objects.create(
        user=user,
        username=username,
        action=action,
        resource_type=resource_type,
        resource_id=str(resource_id) if resource_id else "",
        description=description,
        changes=sanitized_changes,  # 使用清理后的变更
        ip_address=ip_address,
        user_agent=user_agent,
        success=success,
        error_message=error_message,
    )
```

#### 问题 2.4: 公告系统权限不一致
**严重程度**: 🟡 中危

#### 问题 3.2: 错误信息过于详细
**严重程度**: 🟢 低危  
**文件**: `apps/accounts/api.py`  
**类型**: 信息泄露

**问题描述**:
登录失败时返回的错误消息可能帮助攻击者进行枚举攻击。


```python

from django.core.cache import cache

def check_login_rate_limit(username_or_ip):
    key = f"login_attempt:{username_or_ip}"
    attempts = cache.get(key, 0)
    if attempts >= 5:
        return False, 300  # 锁定 5 分钟
    return True, 0

class LoginView(View):
    def post(self, request):
        # ... 获取 username
        allowed, retry_after = check_login_rate_limit(username)
        if not allowed:
            return JsonResponse({
                "detail": "Too many failed attempts. Please try again later."
            }, status=429, headers={'Retry-After': str(retry_after)})
        
        # ... 认证逻辑

            # 记录失败尝试
            cache.incr(f"login_attempt:{username}")
            return JsonResponse({"detail": "Authentication failed."}, status=401)
```

## 三、权限矩阵不一致问题

### 3.1 角色定义不一致

| 文件 | Readonly 权限 | Operator 权限 | Admin 权限 |
|------|---------------|---------------|------------|
| `apps/accounts/utils.py` | 基础访问 | 写操作 | 完全控制 |
| `apps/api/mixins.py` | - | StaffRequiredMixin 允许 | StaffRequiredMixin 允许 |
| `apps/announcements/api.py` | 只看自己 | 看所有 | 完全管理 |
| 前端 `layout.tsx` | 所有页面可访问 | 所有页面可访问 | 管理页面可访问 |

**问题**: 角色权限定义分散在不同文件中，缺乏统一的权限配置。

**修复方案**:
```python
# apps/accounts/permissions.py
class Permission:
    """统一权限配置"""
    
    # 权限等级
    LEVEL_READONLY = 1
    LEVEL_OPERATOR = 2
    LEVEL_ADMIN = 3
    
    # 权限映射
    RESOURCE_PERMISSIONS = {
        # 设备管理
        'device.view': LEVEL_READONLY,
        'device.create': LEVEL_OPERATOR,
        'device.update': LEVEL_OPERATOR,
        'device.delete': LEVEL_ADMIN,
        
        # 用户管理
        'user.view_self': LEVEL_READONLY,
        'user.view_all': LEVEL_ADMIN,
        'user.create': LEVEL_ADMIN,
        'user.update': LEVEL_ADMIN,
        'user.delete': LEVEL_ADMIN,
        
        # 公告管理
        'announcement.view_own': LEVEL_READONLY,
        'announcement.view_all': LEVEL_OPERATOR,
        'announcement.create': LEVEL_ADMIN,
        'announcement.update': LEVEL_ADMIN,
        'announcement.delete': LEVEL_ADMIN,
        
        # 脚本管理
        'script.view': LEVEL_OPERATOR,
        'script.create': LEVEL_OPERATOR,
        'script.update': LEVEL_OPERATOR,
        'script.delete': LEVEL_OPERATOR,
        'script.execute': LEVEL_OPERATOR,
    }
    
    @classmethod
    def has_permission(cls, user, resource: str) -> bool:
        """检查用户是否有某资源的权限"""
        required_level = cls.RESOURCE_PERMISSIONS.get(resource, cls.LEVEL_ADMIN)
        return cls.get_user_level(user) >= required_level
    
    @classmethod
    def get_user_level(cls, user) -> int:
        """获取用户权限等级"""
        if user.is_superuser:
            return cls.LEVEL_ADMIN
        try:
            profile = user.profile
            if profile.role == UserRole.ADMIN:
                return cls.LEVEL_ADMIN
            elif profile.role == UserRole.OPERATOR:
                return cls.LEVEL_OPERATOR
            else:
                return cls.LEVEL_READONLY
        except UserProfile.DoesNotExist:
            return cls.LEVEL_READONLY
```
