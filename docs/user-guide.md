## 2. 系统能做什么

CompostLab V2 是一个围绕堆肥实验构建的平台，主要用于：

- 查看设备是否在线
- 查看设备实时数据和告警状态
- 管理不同类型的实验设备
- 配置设备参数
- 下发控制命令
- 创建自动控制规则和控制脚本
- 管理实验批次和时间窗口
- 查询、分析、导出实验数据

目前平台重点支持的设备类型包括：

- `CP500` 堆肥桶控制器
- `MMCGS` 多点位气体采样/检测控制器
- `SmartCompost` 智能堆肥监测终端

## 4. 仪表盘怎么用

仪表盘是日常最常用的页面，用来快速判断设备是否正常。

### 4.1 仪表盘能看什么

你可以看到：

- 当前设备总数
- 在线设备数
- 危险告警数
- 当前筛选后展示的设备数

每张设备卡片通常会显示：

- 设备名称
- 设备编号
- 设备类型
- 在线状态
- 告警状态
- 关键摘要指标

### 4.2 筛选功能

仪表盘顶部支持按以下条件筛选：

- 关键词搜索
- 在线状态
- 告警状态
- 运行批次

适合的用法：

- 想找某台设备：直接搜索设备名或设备编号
- 想看异常设备：筛选 `Danger`
- 想看离线设备：筛选 `Offline`

### 4.3 不同设备卡片怎么看

#### CP500

CP500 卡片会以示意图方式展示：

- 堆体温度
- 筒壁温度
- 水箱温度
- 加热、水泵、曝气状态

颜色会随温度变化。

操作建议：

- 桌面端可以悬停看更详细的信息
- 手机端建议直接点击卡片进入详情页

#### MMCGS

MMCGS 是“一个控制器 + 多个点位”的设备。

在仪表盘中：

- 整个卡片代表控制器
- 卡片内部的 `P1 / P2 / P3 ...` 表示各个点位

你可以：

- 点击卡片空白区域进入控制器详情
- 点击具体点位进入该点位详情

#### 其他设备

普通设备卡片主要展示：

- 关键指标摘要
- 在线状态
- 告警状态

### 4.4 在线状态说明

常见状态：

- `Online`：近期有数据，设备在线
- `Idle`：一段时间未更新，但可能仍可恢复
- `Offline`：较长时间未更新
- `Unknown`：没有足够信息判断

### 4.5 告警状态说明

常见状态：

- `Danger`：危险告警，需要优先处理
- `Warn`：预警，建议关注
- `OK`：正常
- `No Data`：没有足够数据

## 5. 设备页怎么用

设备页用于集中管理所有设备。

### 5.1 设备列表页能做什么

你可以在设备页：

- 查看全部设备
- 搜索设备
- 查看设备类型
- 查看设备在线状态
- 进入设备详情
- 管理设备基础信息

管理员通常还可以：

- 新建设备
- 编辑设备
- 删除或停用设备

### 5.2 设备类型是什么

设备类型用于帮助平台知道设备应该怎样展示、怎样识别指标、怎样生成控制入口。

常见类型：

- `CP500`
- `MMCGS`
- `Smart Compost`
- `通用设备`

现在平台支持在设备配置中直接指定类型，而不仅仅依赖前端自动识别。

这意味着：

- 更稳定
- 更适合后续维护
- 不容易因为设备命名变化而识别错误

### 5.3 创建设备时建议填写什么

新建设备时，建议尽量完整填写：

- 设备名称
- 设备编号
- 设备类型
- 描述信息
- 配置内容

设备编号通常要与设备端 `device_code` 对应。

## 6. 设备详情页怎么用

设备详情页是单台设备的核心操作页面。

你通常会在这里完成：

- 查看设备状态
- 查看最新数据
- 修改设备配置
- 执行手动控制
- 使用面向普通用户的参数控制面板
- 查看或进入控制脚本相关能力

### 6.1 设备详情页通常有哪些区域

根据设备不同，详情页可能会包含：

- 设备基础信息
- 当前状态
- 关键指标
- 参数配置
- 执行器控制
- 遥测数据
- 历史图表

### 6.2 普通研究人员主要怎么用

如果你不写代码，最常用的是：

- 修改配置参数
- 使用滑块或数字输入框调整参数
- 查看当前状态
- 临时干预设备

例如：

- 调整采样间隔
- 调整曝气时长
- 调整加热相关参数
- 触发临时运行

### 6.3 开发人员主要怎么用

如果你是开发或维护人员，常用的是：

- 查看完整配置 JSON
- 查看通道定义
- 检查控制命令
- 对照脚本和设备协议调试

### 6.4 修改设备配置时要注意什么

当前系统已经朝“只传修改项”这个方向做了优化。

这意味着：

- 你没有修改的字段，不应重复传给设备
- 尤其是 WiFi 密码、MQTT 密码这类字段，不应该把星号掩码再发回设备

实际操作建议：

- 只修改你确定要改的字段
- 保存前检查变化内容
- 如果配置很关键，建议先记录原始值

### 6.5 急停和临时干预

如果设备支持，详情页里可能会看到：

- 急停
- 临时开启某执行器
- 临时关闭某执行器
- 恢复自动控制

使用建议：

- 急停只用于异常或危险情况
- 临时干预后，记得确认是否需要恢复自动控制

## 7. CP500 设备使用说明

CP500 是一个较复杂的设备类型，通常涉及：

- 堆体
- 外壁/夹层
- 水箱
- 水泵
- 加热
- 曝气

### 7.1 你在平台上能看到什么

在仪表盘和详情页中，通常可以看到：

- `TempIn`：堆体温度
- `TempOut1/2/3`：外壁或夹层温度
- `TankTemp`：水箱温度
- `Heater`：加热状态
- `Pump`：水泵状态
- `Aeration`：曝气状态

### 7.2 告警怎么理解

CP500 当前重点关注的异常包括：

- 堆体温度过高
- 水箱与外壁温差过大

例如：

- 当水箱和外壁均温温差达到较大阈值时，系统会标记危险告警

这类告警通常意味着：

- 传热异常
- 加热或循环状态异常
- 设备运行不平衡

### 7.3 操作建议

普通用户建议：

- 先看在线状态
- 再看温度趋势是否合理
- 再看加热/水泵/曝气是否在预期状态

如果出现 `Danger`：

1. 进入设备详情
2. 查看当前温度和执行器状态
3. 必要时急停或临时干预
4. 复查配置参数

## 8. MMCGS 使用说明

MMCGS 不是单个探头，而是一个控制器带多个点位。

### 8.1 MMCGS 的结构

例如：

- `MMCGS001`：控制器
- `MMCGS001-P1 ~ P6`：各采样点位

### 8.2 在平台中怎么理解

你会看到两层对象：

- 控制器层
- 点位层

控制器层负责：

- 汇总展示
- 控制器配置
- 控制器级控制逻辑

点位层负责：

- 具体点位数据查看

### 8.3 常见点位指标

MMCGS 点位常见指标：

- `CO2`
- `O2`
- `CO`
- `H2S`
- `CH4`
- `AirTemp`
- `AirHumidity`

### 8.4 建议使用方式

如果你关心整体运行：

- 先看控制器卡片

如果你关心某个采样位置：

- 点击具体点位进入详情

## 10. 控制脚本怎么用

控制脚本页是平台里自动化能力最强的部分。

如果你不懂代码，也可以使用其中的大部分功能。

### 10.1 控制脚本页能做什么

你可以：

- 创建自动规则
- 创建跨设备联动
- 设置阈值条件
- 设置执行动作
- 查看脚本执行记录
- 使用 Python 脚本模式
- 使用模型控制

### 10.2 规则有哪几类

当前可以理解为几种常见模式：

- 阈值触发
- 定时触发
- 脚本模式
- 跨设备联动

### 10.3 不会写代码时怎么做

最推荐的方式是：

1. 先用规则表单
2. 先做简单条件
3. 先做单设备动作
4. 验证动作正确后，再逐步加复杂条件

例如：

- 当温度高于某值时，启动曝气
- 当 O2 低于某值时，开启某执行器一段时间

### 10.4 会写代码时怎么做

你可以进入脚本模式，直接写 Python 控制逻辑。

脚本中常见能力包括：

- 读取设备当前值
- 读取历史数据
- 调用模型
- 写入运行时状态变量
- 对多个设备下发动作

### 10.5 什么是运行时变量

脚本支持“按脚本 + 设备持久化”的变量。

这意味着你可以做：

- 每次运行计数 +1
- 记录上次状态
- 保存冷却时间
- 做状态机式控制

### 10.6 什么是模型控制

模型控制是指脚本调用一个训练好的模型，输出建议动作。

适合：

- 想做更复杂的自动控制
- 结合历史特征判断
- 尝试数据驱动控制

### 10.7 使用控制脚本的建议

建议顺序：

1. 先确认设备手动控制正常
2. 再建立简单规则
3. 再引入多条件
4. 最后再尝试 Python 脚本或模型控制

## 11. 运行批次怎么用

运行批次页用于管理实验过程，而不是单台设备本身。

### 11.1 Run 是什么

一个 `Run` 可以理解为：

- 一次实验
- 一个堆肥批次
- 一个试验周期

### 11.2 Window 是什么

`Window` 是批次中的时间窗口。

它用于表示：

- 某段时间内
- 哪些设备
- 属于哪个处理组

### 11.3 适合怎么用

例如你要做多组实验，可以：

1. 创建一个 Run
2. 为不同阶段建立多个 Window
3. 把设备分配到不同组
4. 后续按 Run 汇总和导出数据

### 11.4 批次页能做什么

你可以：

- 新建批次
- 编辑批次
- 管理窗口
- 查看批次数据
- 导出批次数据
- 上传实验附件

## 14. 常见操作流程

## 14.1 第一次上手推荐流程

1. 登录系统
2. 先看仪表盘，了解设备整体状态
3. 进入设备页，确认设备类型和名称是否正确
4. 点开单台设备详情，熟悉参数和状态
5. 再去控制脚本页尝试简单规则
6. 最后再使用运行批次和数据探索

## 14.2 添加新设备后的推荐流程

1. 新建设备
2. 检查设备类型是否正确
3. 检查通道是否完整
4. 确认设备开始上报
5. 去仪表盘确认卡片展示是否正常
6. 必要时补充配置和控制规则

## 14.3 出现异常告警时的推荐流程

1. 在仪表盘定位异常设备
2. 进入设备详情
3. 查看当前状态和关键指标
4. 判断是否需要临时干预或急停
5. 检查配置参数和控制脚本
6. 复查最近数据趋势

## 15. 常见问题

### 15.1 设备离线怎么办

优先检查：

- 设备是否断电
- WiFi 是否异常
- MQTT 是否可达
- 设备是否实际还在上报

### 15.2 数据有了，但仪表盘显示不对怎么办

优先检查：

- 设备类型是否正确
- 通道 code 是否符合平台识别规则
- 通道 metric / display_name 是否配置正确

### 15.3 控制命令发了没有反应怎么办

优先检查：

- 设备是否在线
- 对应执行器通道是否存在
- 是否处于急停状态
- 是否被自动控制或手动锁定逻辑拦截

### 15.4 脚本规则没生效怎么办

优先检查：

- 规则是否启用
- 条件是否真的满足
- 目标设备是否正确
- 执行动作是否有效
- 脚本执行记录里是否有错误

### 15.5 手机上为什么没有 hover 详情

这是有意为之。

因为手机端 hover 很容易误触，所以移动端通常改为：

- 直接点击进入详情
- 避免悬停弹层影响滑动操作

## 17. 术语解释

### 设备

平台中的一个独立对象，可以是单台终端，也可以是一个控制器。

### 通道

设备的一个测量或控制项，例如：

- 温度
- O2
- CO2
- 加热状态

### 设备类型

平台识别设备展示方式和控制方式的依据，例如 `CP500`、`MMCGS`。

### Run

一次实验批次。

### Window

批次中的时间窗口或阶段。

### 控制脚本

用于让系统自动执行控制逻辑的规则或 Python 脚本。

### 模型控制

通过机器学习模型辅助做控制决策。

## 18. 给用户的最后建议

如果你是第一次使用这个平台，最重要的是：

- 先学会看状态
- 再学会改参数
- 最后再学会自动控制

不要一开始就上复杂联动或复杂脚本。

平台的正确使用顺序通常是：

1. 设备在线
2. 数据正常
3. 手动控制正常
4. 自动规则再上线

这样最稳，也最不容易把问题混在一起。
