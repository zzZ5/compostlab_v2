# 遥测数据访问控制修复说明

## 问题概述

**问题编号**: 1.2
**严重程度**: 🔴 高危
**问题描述**: 遥测数据查询接口无访问控制

### 原始问题

遥测数据查询接口只使用了 `BasicAuthMixin` 进行身份认证，但没有基于角色的访问控制。这意味着：

- 只读用户可以访问所有历史数据
- 如果存在导出功能，可能导致大规模数据泄露
- 影响数据隐私和合规性

### 涉及的文件

- `apps/telemetry/api.py`: 遥测数据查询接口
- `apps/api/mixins.py`: 认证和授权 Mixin

---

## 修复方案

### 1. 创建 TelemetryAccessMixin

在 `apps/api/mixins.py` 中添加了 `TelemetryAccessMixin` 类：

```python
class TelemetryAccessMixin:
    """
    遥测数据访问控制 Mixin

    为敏感数据查询添加时间范围限制：
    - readonly 用户只能查询最近 7 天的数据
    - operator 和 admin 用户可以查询任意时间范围的数据
    """

    # 默认配置
    DEFAULT_READONLY_DAYS = 7  # 只读用户默认只能查询最近 7 天

    def get_adjusted_time_range(self, request, dt_from, dt_to):
        """获取调整后的时间范围（为只读用户自动限制）"""
        # ... 实现逻辑
```

**核心功能**:
- 基于用户角色动态调整时间范围
- 自动限制只读用户的查询时间到最近 7 天
- 管理员和操作员不受限制

### 2. 修改遥测 API 视图

修改了以下视图类，添加 `TelemetryAccessMixin`：

```python
# 修改前
class DeviceTelemetryView(BasicAuthMixin, View):
    # ...

# 修改后
class DeviceTelemetryView(TelemetryAccessMixin, BasicAuthMixin, View):
    # ...
```

**涉及的视图**:
1. `DeviceTelemetryView`: 单设备遥测数据查询
2. `DeviceChannelTelemetryView`: 单设备单通道遥测数据查询
3. `MultiDeviceTelemetryView`: 多设备遥测数据查询
4. `DeviceExportView`: 遥测数据导出

### 3. 时间范围调整逻辑

在每个视图的 `get` 方法中添加时间范围调整：

```python
def get(self, request, device_id: int):
    # ... 获取 dt_from, dt_to

    # 对只读用户自动限制时间范围
    dt_from, dt_to, was_limited = self.get_adjusted_time_range(request, dt_from, dt_to)

    # ... 使用调整后的 dt_from, dt_to 进行查询
```

## 安全性改进

### 1. 只读用户限制
- ✅ 只读用户只能查询最近 7 天的遥测数据
- ✅ 超过 7 天的查询请求会被自动调整到允许的时间范围
- ✅ 未指定时间范围的请求默认限制到最近 7 天

### 2. 操作员和管理员权限
- ✅ 操作员和用户可以查询任意时间范围的数据
- ✅ 支持历史数据分析和长期趋势查询

### 3. 超级管理员
- ✅ 超级管理员拥有完全访问权限

### 4. 导出功能保护
- ✅ `DeviceExportView` 同样受到时间范围限制保护
- ✅ 防止只读用户批量导出历史数据

## 配置选项

可以在 `TelemetryAccessMixin` 子类中自定义配置：

```python
class CustomTelemetryAccessMixin(TelemetryAccessMixin):
    DEFAULT_READONLY_DAYS = 30  # 将只读用户限制改为 30 天
```

或在 `settings.py` 中添加配置（需要扩展 Mixin 以支持）：

```python
TELEMETRY_READONLY_DAYS = 7
```
