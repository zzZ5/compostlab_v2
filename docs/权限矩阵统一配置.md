# 权限矩阵统一配置

## 问题描述

在修复之前，项目存在权限定义不一致的问题：

| 文件 | Readonly 权限 | Operator 权限 | Admin 权限 |
|------|---------------|---------------|------------|
| `apps/accounts/utils.py` | 基础访问 | 写操作 | 完全控制 |
| `apps/api/mixins.py` | - | StaffRequiredMixin 允许 | StaffRequiredMixin 允许 |
| `apps/announcements/api.py` | 只看自己 | 看所有 | 完全管理 |
| 前端 `layout.tsx` | 所有页面可访问 | 所有页面可访问 | 管理页面可访问 |

**问题**：角色权限定义分散在不同文件中，缺乏统一的权限配置。

## 解决方案

创建了统一的权限配置模块 `apps/permissions/`，集中管理所有权限规则。

### 目录结构

```
apps/permissions/
├── __init__.py          # 模块入口
├── config.py            # 权限矩阵配置
├── checks.py            # 权限检查工具
└── mixins.py            # 权限验证 Mixins
```

## 角色定义

### 角色等级

| 角色 | 等级 | 描述 |
|------|------|------|
| READONLY | 1 | 只读用户，只能查看数据 |
| OPERATOR | 2 | 操作员，可以执行写操作 |
| ADMIN | 3 | 管理员，完全控制权限 |

### 权限规则

- **is_superuser**: 超级管理员，拥有所有权限
- **其他用户**: 完全依赖 `UserProfile.role` 判断权限
  - `is_staff` 不再自动赋予 admin 权限
  - `is_staff` 用户也必须有对应的 `UserProfile.role`

## 使用指南

### 1. 导入模块

```python
from apps.permissions import (
    ResourceType,
    ActionType,
    get_required_role_for_action,
    has_permission,
    check_permission,
    RoleRequiredMixin,
    OperatorRequiredMixin,
    AdminRequiredMixin,
)
```

### 2. 基于角色的权限检查

```python
from apps.permissions import has_permission
from apps.accounts.models import UserRole

# 检查用户是否有 admin 权限
if has_permission(request.user, UserRole.ADMIN):
    # 执行管理员操作
    pass
```

### 3. 基于资源的权限检查

```python
from apps.permissions import check_permission, ResourceType, ActionType

# 检查用户是否可以删除设备
if check_permission(request.user, ResourceType.DEVICE, ActionType.DELETE):
    # 执行删除操作
    pass
```

### 4. 使用 Mixin 在视图中

#### 基于角色的 Mixin

```python
from apps.permissions import OperatorRequiredMixin, AdminRequiredMixin

# 只允许操作员及以上
class DeviceUpdateView(OperatorRequiredMixin, JWTAuthMixin, View):
    def post(self, request):
        pass

# 只允许管理员
class UserCreateView(AdminRequiredMixin, JWTAuthMixin, View):
    def post(self, request):
        pass
```

#### 基于资源和操作的 Mixin

```python
from apps.permissions import ResourcePermissionMixin, ResourceType, ActionType

class DeviceDeleteView(
    ResourcePermissionMixin,
    JWTAuthMixin,
    View
):
    resource_type = ResourceType.DEVICE
    action_type = ActionType.DELETE
    
    def delete(self, request, device_id):
        pass
```

#### 自动判断读/写权限的 Mixin

```python
from apps.permissions import ReadOrWritePermissionMixin, ResourceType

class DeviceListView(
    ReadOrWritePermissionMixin,
    JWTAuthMixin,
    View
):
    resource_type = ResourceType.DEVICE
    
    def get(self, request):
        # 自动使用 READ 权限
        pass
    
    def post(self, request):
        # 自动使用 WRITE 权限
        pass
```

## 迁移指南

### 已更新的文件

1. **apps/accounts/utils.py**
   - `has_permission()` 函数现在内部使用新的权限检查模块
   - 保持向后兼容，支持字符串和 UserRole 枚举

2. **apps/accounts/mixins.py**
   - `RoleRequiredMixin`, `OperatorRequiredMixin`, `AdminRequiredMixin` 保留
   - 添加注释说明建议使用新的权限模块

3. **apps/api/mixins.py**
   - `StaffRequiredMixin` 保持不变
   - 添加注释说明建议使用新的权限模块

4. **apps/announcements/api.py**
   - `AnnouncementListView` 使用 `OperatorRequiredMixin`
   - `AnnouncementCreateView` 使用 `AdminRequiredMixin`
   - 移除手动权限检查代码

### 未来更新建议

对于现有代码，可以逐步迁移到新的权限模块：

```python
# 旧代码
from apps.accounts.mixins import RoleRequiredMixin

# 新代码
from apps.permissions import RoleRequiredMixin
```

新代码推荐使用：

```python
from apps.permissions import ResourcePermissionMixin, ResourceType, ActionType

class MyView(ResourcePermissionMixin, JWTAuthMixin, View):
    resource_type = ResourceType.DEVICE
    action_type = ActionType.WRITE
```

## 注意事项

1. **向后兼容**: 旧的权限检查函数和 Mixins 仍然可用，可以逐步迁移
2. **is_staff 不再授予权限**: `is_staff` 用户必须有对应的 `UserProfile.role`
3. **超级用户权限**: `is_superuser` 拥有所有权限，不需要 profile
4. **禁用用户**: `is_active=False` 的用户没有任何权限
5. **无 profile 用户**: 只有 readonly 权限

## 示例：添加新资源权限

假设要添加新的资源类型 `PRODUCT`：

1. 在 `apps/permissions/config.py` 的 `ResourceType` 枚举中添加：

```python
class ResourceType(str, Enum):
    # ... 现有资源
    PRODUCT = "product"
```

2. 在 `PermissionMatrix.MATRIX` 中添加权限配置：

```python
MATRIX: Dict[ResourceType, Dict[ActionType, UserRole]] = {
    # ... 现有配置
    ResourceType.PRODUCT: {
        ActionType.READ: UserRole.READONLY,
        ActionType.WRITE: UserRole.OPERATOR,
        ActionType.CREATE: UserRole.OPERATOR,
        ActionType.DELETE: UserRole.ADMIN,
    },
}
```

3. 在视图中使用：

```python
from apps.permissions import ResourcePermissionMixin, ResourceType, ActionType

class ProductUpdateView(
    ResourcePermissionMixin,
    JWTAuthMixin,
    View
):
    resource_type = ResourceType.PRODUCT
    action_type = ActionType.WRITE
```
