# 请求速率限制修复说明

## 问题描述

**问题编号**: 2.1
**严重程度**: 🟡 中危
**文件**: 所有 API 视图

所有 API 接口都没有实施请求速率限制，攻击者可以通过高频请求导致：

1. 资源耗尽（CPU/内存/数据库连接）
2. 暴力破解密码
3. 枚举用户信息

## 修复方案

使用 Django Cache 实现请求速率限制，无需额外依赖。

### 1. 创建速率限制 Mixin

**文件**: `apps/accounts/rate_limit.py`

```python
class RateLimitedMixin:
    """
    请求速率限制 Mixin

    特性：
    - 基于 IP + 用户 ID + 视图名称进行限流
    - 已认证用户：使用用户 ID 作为 key
    - 未认证用户：使用 IP 地址作为 key
    - 支持自定义限流参数
    """

    rate_limit = 100     # 默认：每个时间窗口允许 100 次请求
    rate_period = 60      # 默认：时间窗口为 60 秒
    rate_key = None       # 可选：自定义限流 key 前缀

    def dispatch(self, request, *args, **kwargs):
        """在请求处理前检查速率限制"""
        key = self._get_rate_limit_key(request)
        count = cache.get(key, 0)
        
        if count >= self.rate_limit:
            return JsonResponse(
                {"detail": "Too many requests. Please try again later."},
                status=429,
            )
        
        # 增加计数并设置过期时间
        cache.set(key, count + 1, self.rate_period)
        
        return super().dispatch(request, *args, **kwargs)
```

### 2. 预定义的限流 Mixin

提供针对不同场景的预定义限流 Mixin：

| Mixin 名称 | 用途 | 限制 | 时间窗口 |
|------------|------|------|---------|
| `LoginRateLimitedMixin` | 登录接口 | 5 次 | 5 分钟 |
| `AuthRateLimitedMixin` | 认证相关（注册、修改密码等） | 3 次 | 1 小时 |
| `APICreateRateLimitedMixin` | 创建资源、上传数据 | 30 次 | 1 分钟 |
| `APIReadRateLimitedMixin` | 列表查询、数据读取 | 100 次 | 1 分钟 |

### 3. 应用速率限制

**登录接口** (`apps/accounts/api.py`):

```python
from .rate_limit import LoginRateLimitedMixin, AuthRateLimitedMixin

@method_decorator(csrf_exempt, name='dispatch')
class LoginView(LoginRateLimitedMixin, View):
    """
    POST /api/v2/auth/login
    速率限制: 5 次 / 5 分钟
    """
    def post(self, request):
        # ...
```

**修改密码接口** (`apps/accounts/api.py`):

```python
class ChangePasswordView(AuthRateLimitedMixin, JWTAuthMixin, View):
    """
    POST /api/v2/auth/change-password
    速率限制: 3 次 / 小时
    """

        # ...
```

### 4. 自定义限流参数

如果需要不同的限流策略，可以覆盖默认参数：

```python
class MyCustomView(RateLimitedMixin, View):
    rate_limit = 10       # 10 次
    rate_period = 60       # 每分钟
    rate_key = "my_api"    # 自定义 key 前缀

    def get(self, request):
        # ...
```

## 安全改进

1. **防止暴力破解**
   - 登录接口限制：5 次/5 分钟
   - 有效阻止密码暴力破解攻击

2. **防止 DoS 攻击**
   - 所有接口都有速率限制
   - 防止高频请求耗尽资源

3. **细粒度控制**
   - 已认证用户：按用户 ID 限流
   - 未认证用户：按 IP 地址限流
   - 不同 IP 不会相互影响

## 限流 Key 设计

限流 key 的格式：`{prefix}:{view_name}:{identifier}`

示例：
- `login:LoginView:127.0.0.1` - 未认证用户的登录请求
- `login:LoginView:123` - 用户 ID 为 123 的登录请求
- `auth:ChangePasswordView:127.0.0.2` - 修改密码请求

## 客户端处理

当接口返回 429 状态码时，客户端应该：

1. 显示友好的错误提示
2. 延迟后重试
3. 实现指数退避策略

示例：

```typescript
async function makeRequest(url: string, retries = 3): Promise<any> {
  try {
    const response = await fetch(url);
    
    if (response.status === 429) {
      const retryAfter = response.headers.get('Retry-After');
      const delay = retryAfter ? parseInt(retryAfter) * 1000 : 5000;
      
      message.warning("请求过于频繁，请稍后重试");
      
      if (retries > 0) {
        await sleep(delay);
        return makeRequest(url, retries - 1);
      }
    }
    
    return response;
  } catch (error) {
    // ...
  }
}
```

## 后续建议

1. **为更多接口添加限流**
   - 用户注册接口
   - 设备创建接口
   - 数据上传接口

2. **使用 Redis 作为 Cache 后端**
   - 更好的性能
   - 支持更复杂的限流策略（如令牌桶算法）
   - 分布式环境支持

3. **监控和告警**
   - 记录被限流的请求
   - 监控异常高频请求
   - 发现攻击行为及时告警

4. **实现更复杂的限流算法**
   - 令牌桶（Token Bucket）
   - 漏桶（Leaky Bucket）
   - 滑动窗口计数器

## 总结

通过实现基于 Django Cache 的速率限制机制，我们有效防止了：

- 暴力破解密码攻击
- DoS 攻击
- 资源耗尽

主要特点：
- 无需额外依赖
- 基于用户 ID 和 IP 的细粒度限流
- 可自定义限流参数
- 易于集成到现有代码
