# 用户权限检查逻辑错误修复说明

## 问题概述

**问题编号**: 1.3
**严重程度**: 🔴 高危
**问题描述**: 用户权限检查存在逻辑错误

### 原始问题

`has_permission` 函数在检查 `is_staff` 用户时，允许其访问所有角色（readonly/operator/admin），这不是预期的行为。通常 `is_staff` 用户应该只拥有与其 `UserProfile.role` 相对应的权限。

**原始代码** (apps/accounts/utils.py:135-137):
```python
# 管理员（Django staff）也算 admin 角色
if user.is_staff and required_role in ["readonly", "operator", "admin"]:
    return True
```

### 安全风险

- **权限提升**: `is_staff=True` 但 `role='operator'` 的用户可以访问 admin 级别的资源
- **权限边界模糊**: Django 的 `is_staff` 与应用的角色系统不一致
- **违反最小权限原则**: 用户可能获得超出预期的权限
- **审计困难**: 权限检查逻辑不一致，难以审计

### 影响范围

所有使用 `has_permission` 函数进行权限检查的地方：
- 用户管理接口
- 设备管理接口
- 公告管理接口
- 脚本管理接口
- 其他需要权限验证的业务逻辑

## 修复方案

### 修复后的代码

**修复后** (apps/accounts/utils.py:117-153):
```python
def has_permission(user, required_role):
    """
    检查用户是否有足够权限

    角色权限等级：
    - readonly (1): 只读权限
    - operator (2): 操作权限
    - admin (3): 管理权限

    权限规则：
    - is_superuser: 超级管理员，拥有所有权限
    - 其他用户: 完全依赖 UserProfile.role 判断权限
      - is_staff 不再自动赋予 admin 权限
      - is_staff 用户也必须有对应的 UserProfile.role
    """
    if not user or not user.is_authenticated:
        return False

    # 超级用户总是有权限
    if user.is_superuser:
        return True

    # 检查用户是否有 UserProfile
    try:
        profile = user.profile
    except UserProfile.DoesNotExist:
        # 没有 profile 的用户，默认被视为 readonly
        return required_role == "readonly"

    # 检查用户是否启用
    if not profile.is_active:
        return False

    # 角色等级：readonly < operator < admin
    role_levels = {"readonly": 1, "operator": 2, "admin": 3}
    user_level = role_levels.get(profile.role, 0)
    required_level = role_levels.get(required_role, 999)

    return user_level >= required_level
```

### 核心改进

1. **移除 `is_staff` 自动赋权**:
   - 不再自动为 `is_staff=True` 的用户赋予 admin 权限
   - 完全依赖 `UserProfile.role` 来判断权限

2. **统一权限检查逻辑**:
   - 所有用户（包括 `is_staff` 用户）都通过 `UserProfile.role` 判断权限
   - Django 的 `is_staff` 仅用于控制是否可以访问 Django Admin 后台
   - 应用权限完全由 `UserProfile.role` 控制

3. **明确权限边界**:
   - `is_superuser`: 拥有所有权限
   - 其他用户: 完全依赖 `UserProfile.role`
   - 没有权限歧义

## 迁移指南

### 现有用户处理

修复后，现有 `is_staff=True` 但 `UserProfile.role` 不等于 `admin` 的用户权限会被降低：

**场景 1**: `is_staff=True`, `role='operator'`
- 修复前: 可以访问 admin 级别资源（错误）
- 修复后: 只能访问 operator 和 readonly 级别资源（正确）
- 影响: 无法再访问 admin 管理功能

**场景 2**: `is_staff=True`, `role='readonly'`
- 修复前: 可以访问 operator 和 admin 级别资源（错误）
- 修复后: 只能访问 readonly 级别资源（正确）
- 影响: 权限被限制为只读

**建议操作**:
1. 审计所有 `is_staff=True` 的用户
2. 确认他们的 `UserProfile.role` 是否正确
3. 如果用户需要 admin 权限，确保 `role='admin'`

### 数据库检查 SQL

```sql
-- 查找 is_staff=True 但 role != admin 的用户
SELECT
    u.id,
    u.username,
    u.is_staff,
    up.role
FROM auth_user u
LEFT JOIN accounts_userprofile up ON u.id = up.user_id
WHERE u.is_staff = TRUE
  AND (up.role IS NULL OR up.role != 'admin');
```

### 修正脚本

```python
from django.contrib.auth import get_user_model
from apps.accounts.models import UserProfile, UserRole

User = get_user_model()

# 查找所有 is_staff=True 但 role != admin 的用户
users = User.objects.filter(
    is_staff=True
).select_related('profile')

for user in users:
    profile = user.profile
    if not profile:
        print(f"用户 {user.username} 没有 profile，跳过")
        continue

    if profile.role != UserRole.ADMIN:
        print(f"用户 {user.username}: is_staff=True, role={profile.role}")
```
