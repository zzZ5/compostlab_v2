# 设备说明手册

## 1. 这份文档是做什么的

这份文档专门说明平台当前接入的设备类型、设备结构、常见指标、控制方式和在平台中的展示逻辑。

适合阅读的人：

- 普通研究人员
- 设备维护人员
- 新接手项目的人
- 需要理解设备与平台映射关系的人

---

## 2. 当前设备分类

平台目前主要面向三类设备：

- `CP500`
- `MMCGS`
- `SmartCompost`

它们的差异非常大：

- `CP500` 偏控制型设备
- `MMCGS` 偏多点位采样型设备
- `SmartCompost` 偏轻量监测型设备

这也是为什么平台会根据设备类型使用不同的仪表盘卡片、详情页布局和控制入口。

---

## 3. CP500 设备说明

## 3.1 设备定位

`CP500` 是堆肥桶控制器，平台里把它视为一台“带温控和执行器的复合设备”。

它通常负责：

- 监测堆体温度
- 监测外壁/夹层温度
- 监测水箱温度
- 控制加热
- 控制循环水泵
- 控制曝气

## 3.2 结构理解

从平台建模角度，可以把 CP500 理解为：

- 内桶：堆体所在区域
- 外壁/夹层：热交换层
- 水箱：被加热与循环的水源
- 水泵：负责把水送入夹层并回流
- 曝气：把空气送入桶体内部

这也是为什么仪表盘上 CP500 采用了专门的示意图，而不是普通的数字卡片。

## 3.3 常见指标

平台中 CP500 常见通道包括：

- `TempIn`
  - 堆体温度
- `TempOut1`
  - 外壁温度 1
- `TempOut2`
  - 外壁温度 2
- `TempOut3`
  - 外壁温度 3
- `TankTemp`
  - 水箱温度
- `Heater`
  - 加热状态
- `Pump`
  - 水泵状态
- `Aeration`
  - 曝气状态
- `EmergencyState`
  - 急停状态

## 3.4 在平台中怎么看

### 仪表盘

在仪表盘中，CP500 使用专用图形卡片展示：

- 中间主桶代表堆体
- 外层代表夹层/外壁
- 右下或侧边水箱代表加热与循环系统
- 颜色代表温度梯度
- 线条动画代表执行器运行状态

### 设备详情

在设备详情页里，CP500 一般会有：

- 当前状态
- 关键温度
- 普通用户参数配置
- 临时干预
- 高级配置或脚本入口

## 3.5 告警重点

CP500 当前建议重点关注的异常包括：

- 堆体温度过高
- 水箱与外壁均温温差过大
- 执行器状态异常
- 长时间离线

其中“水箱与外壁温差过大”通常表示：

- 加热与传热不平衡
- 循环异常
- 传感器或运行状态异常

## 3.6 普通用户操作建议

如果你不写代码，使用 CP500 时建议按这个顺序判断：

1. 看设备是否在线
2. 看堆体温度是否合理
3. 看外壁温度和水箱温度是否协调
4. 看加热、水泵、曝气是否在预期状态
5. 再考虑是否需要手动干预

## 4. MMCGS 设备说明

## 4.1 设备定位

`MMCGS` 不是单点设备，而是一个“控制器 + 多个点位”的组合。

它通常用于：

- 多点位气体采样
- 多点位环境监测
- 统一控制和统一上报

## 4.2 结构理解

平台中 MMCGS 通常分成两层：

- 控制器，例如 `MMCGS001`
- 点位，例如 `MMCGS001-P1` 到 `MMCGS001-P6`

也就是说：

- 控制器负责整套装置的控制和注册
- 点位负责各采样位的具体测量结果

## 4.3 常见点位指标

MMCGS 常见上报指标：

- `CO2`
- `O2`
- `CO`
- `H2S`
- `CH4`
- `AirTemp`
- `AirHumidity`

这些指标通常是点位级别的，而不是整个控制器的单一数值。

## 4.4 在平台中怎么看

### 仪表盘

在仪表盘里：

- 整张 MMCGS 卡片代表控制器
- 卡片里的 `P1 / P2 / P3...` 代表各个点位

当前交互逻辑建议这样理解：

- 点击卡片空白区域：进入控制器详情
- 点击某个点位：进入该点位设备详情

### 控制器视角

控制器视角适合看：

- 控制器整体是否在线
- 一共有多少点位
- 各点位是否在线
- 各点位的总体状态

### 点位视角

点位视角适合看：

- 该点位的具体气体和温湿度数据
- 该点位的详细趋势

## 4.5 使用建议

如果你是普通研究人员：

- 先看控制器卡片是否正常
- 再点击具体点位查看细节

如果你是维护人员：

- 先确认控制器在线
- 再看各点位是否有缺失、离线或异常

## 5. SmartCompost 设备说明

## 5.1 设备定位

`SmartCompost` 更偏向监测型终端，适合较轻量的堆肥监测场景。

相比 CP500，它通常：

- 执行器更少
- 环境指标更突出
- 更适合做环境与气体趋势观察

## 5.2 常见指标

常见通道包括：

- `CO2`
- `O2`
- `RoomTemp`
- `AirTemp`
- `AirHumidity`

## 5.3 在平台中怎么看

这类设备在平台里一般会以普通指标卡片展示：

- 关键温度
- O2 / CO2
- 在线状态
- 告警状态

## 5.4 使用建议

更适合用于：

- 环境趋势监控
- 基础数据采集
- 较轻量的自动规则触发

## 7. 设备类型与平台映射关系

平台之所以要识别设备类型，是因为不同设备需要不同的逻辑：

- 指标识别方式不同
- 仪表盘展示方式不同
- 告警规则不同
- 控制入口不同
- 控制脚本可选动作不同

例如：

- `CP500` 要看加热、水泵、曝气与多个温度
- `MMCGS` 要看控制器与多个点位关系
- `SmartCompost` 要看环境指标和简单控制

这也是为什么“设备类型”已经被放进设备编辑和配置流程中，而不是完全依赖前端猜测。

## 9. 使用中的常见误区

### 9.1 把控制器和点位当成同一个对象

MMCGS 最容易出现这个误区。

要记住：

- 控制器是控制器
- 点位是点位
- 平台里两者既有关联，也有各自详情页

### 9.2 只看一个温度就判断 CP500 状态

CP500 不建议只看单个温度。

更合理的是同时看：

- 堆体温度
- 外壁温度
- 水箱温度
- 执行器状态

### 9.3 设备名改了，就以为平台逻辑会自动完全对应

设备名只是显示层信息。

真正影响平台识别的通常还包括：

- 设备类型
- 通道 code
- 通道 metric
- 配置中的元信息
